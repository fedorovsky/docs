# TRACK-12: Identity пользователя и согласие на трекинг

*Тикет от продакта.*

Приложение должно знать identity пользователя и спрашивать согласие на маркетинговый и аналитический трекинг. Бэкенд в работе, контракт согласован: методы конфига и согласия пока фейковые, с задержкой, иногда с ошибкой, помнят выбор между перезагрузками.

## Конфиг на старте

```
marketingTrackingId      null, пока статус не Accepted; при consentRequired = false всегда null
analyticsTrackingId      то же
deviceId                 пока константа
temporaryId              случайное, новое на каждом старте
consentRequired          true/false, только из конфига
marketingConsentStatus   0 Declined, 1 Accepted, 2 NotDecided
analyticsConsentStatus   то же
```

`consentRequired = true`: на первом старте оба статуса `NotDecided`. `false`: оба `NotDecided`, tracking ID не выдаются (оба `null`), блоки согласия скрыты.

## Блоки согласия

Два блока на одной странице, не модалки. В каждом переключатели marketing и analytics с текущими статусами, кнопки «Сохранить» и «Принять всё».

- **Стартовый**: виден при `consentRequired = true` и хотя бы одном `NotDecided`.
- **Настройки**: виден при `consentRequired = true`; здесь же согласие отзывают.
- Выключенный переключатель при сохранении = `Declined`.

## Метод согласия

Один вызов с обоими полями, как стоят переключатели; поля независимы. Возвращает оба tracking ID:

- `Accepted` → `Accepted`: ID прежний.
- `Declined` или `NotDecided` → `Accepted`: новый ID, прежний не возвращается.
- Отказ или отзыв: `null`, статус `Declined`.
- Ошибка на весь вызов: ни одно поле не меняется.

## Обсервер identity

Identity-поля: все семь полей конфига. Обсервер отдаёт их всем подписчикам при старте и при каждом изменении, без перезагрузки; если ничего не изменилось, не вызывает.

Три фейковых подписчика (запоминают, что пришло) пишут оба tracking ID и `temporaryId`; при `consentRequired = false` ещё `deviceId`, при `true` вместо него оба статуса согласия, `deviceId` писать нельзя:

1. Хедеры к бэкенду: плюс `consentRequired`; хедер с `null` убирается, имена придумать.
2. Коллектор аналитики: `null` как есть.
3. Гейм-конфиг: `null` как есть.

## Мониторинг (отладка, потом уберём)

Рядом с настройками три блока, по одному на подписчика: текущее состояние и время обновления. Макетов нет.

Готово, когда каждое согласие можно дать и отозвать отдельно, а блоки мониторинга сразу показывают актуальные поля.
