# TRACK-12: Identity пользователя и согласие на трекинг

*Тикет от продакта.*

Приложение должно знать identity пользователя и спрашивать согласие на маркетинговый и аналитический трекинг. Бэкенд ещё делают: контракт согласован, методы (получение конфига и согласие) пока фейковые. Фейки ведут себя как настоящие: с задержкой, иногда с ошибкой, и помнят выбор пользователя между перезагрузками.

## Конфиг на старте

```
marketingTrackingId
analyticsTrackingId
deviceId                 пока константа
temporaryId              случайное, новое на каждом старте
consentRequired          true/false, задаётся только конфигом
marketingConsentStatus   0 Declined, 1 Accepted, 2 NotDecided
analyticsConsentStatus   то же
```

- Tracking ID есть только при статусе `Accepted`, иначе `null`.
- `consentRequired = true`: на первом старте оба статуса `NotDecided`.
- `consentRequired = false`: оба статуса `Accepted`, оба ID в конфиге, блоки согласия не показываем.

## Блоки согласия

Два блока на одной странице, не модалки: **стартовый** и **настройки**. В каждом два переключателя (marketing, analytics) с текущими статусами, кнопки «Сохранить» и «Принять всё».

- Стартовый виден, если `consentRequired = true` и хотя бы один статус `NotDecided`.
- Настройки видны, если `consentRequired = true`.
- При сохранении выключенный переключатель = `Declined`. Так же через настройки согласие отзывают.

## Метод согласия

Один вызов с обоими полями (как стоят переключатели), поля обрабатываются независимо. Возвращает `marketingTrackingId` и `analyticsTrackingId`:

- `Accepted` → `Accepted`: ID прежний.
- `Declined` или `NotDecided` → `Accepted`: новый ID (после отзыва прежний не возвращается).
- Отказ или отзыв: `null`, статус `Declined`.
- Ошибка относится ко всему вызову: ни одно поле не меняется.

## Обсервер identity

Identity-поля — все семь полей конфига. Обсервер вызывает всех подписчиков со всеми полями: сразу при старте и при каждом изменении, без перезагрузки. Если после сохранения ничего не изменилось, не вызывает.

Подписчиков три, пока фейковые: просто запоминают, что пришло. Все пишут оба tracking ID и `temporaryId`. При `consentRequired = false` к ним добавляется `deviceId`, при `true` вместо него `marketingConsentStatus` и `analyticsConsentStatus`; `deviceId` при `true` писать нельзя.

1. Хедеры запросов к бэкенду: дополнительно `consentRequired`, хедер с `null` убирается, имена придумать.
2. Коллектор аналитики: `null` пишется как есть.
3. Гейм-конфиг: `null` пишется как есть.

## Мониторинг (отладка, потом уберём)

Рядом с блоком настроек три блока, по одному на подписчика: текущее состояние и время последнего обновления. Макетов нет, дизайнер подключится позже.

Готово, когда каждое согласие можно дать и отозвать отдельно, и все три блока мониторинга сразу показывают актуальные поля.
