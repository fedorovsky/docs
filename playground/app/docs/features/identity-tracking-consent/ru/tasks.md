# Identity пользователя и согласие на трекинг — Задачи

Реализуют флоу identity из [спецификации](./spec.md): сначала каркас, фейковый API, обсервер, подписчики и UI-компоненты; страница, которая их показывает, идёт последней, поэтому до проверки ничего не доступно.

## Задачи

- [x] **T1. Создать каркас приложения**
  - Покрывает: `setup`
  - Файлы: `package.json`, `vite.config.ts`, `tsconfig.json`, `index.html`, `src/main.tsx`, `src/App.tsx`
  - Что сделать: создать приложение Vite + React + TypeScript с Vitest и Testing Library в `playground/app/`, которое рендерит пустую страницу (раздел «Контекст и текущее состояние»)
  - Готово, когда: `npm run build` и `npm test` проходят
  - Зависит от: —
- [x] **T2. Добавить типы identity и обсервер**
  - Покрывает: R8
  - Файлы: `src/identity/types.ts`, `src/identity/identityObserver.ts`, `src/identity/identityObserver.test.ts`
  - Что сделать: `ConsentStatus`, `IdentityFields`, `ConsentRequest`, `ConsentResponse` и `createIdentityObserver`, как в разделе «Компоненты и изменения»
  - Готово, когда: тесты показывают, что подписчики вызываются при первом `set`, при изменённом поле, не вызываются при идентичном `set`, а поздний подписчик вызывается сразу
  - Зависит от: T1
- [x] **T3. Реализовать фейковый API identity**
  - Покрывает: R1, R2, R6, R11
  - Файлы: `src/api/identityApi.ts`, `src/api/fakeIdentityApi.ts`, `src/api/fakeIdentityApi.test.ts`
  - Что сделать: `IdentityApi` и `createFakeIdentityApi` с задержкой, долей ошибок, хранилищем и правилами ID (раздел «API / интерфейсы»)
  - Готово, когда: тесты покрывают первый старт в обоих режимах `consentRequired`, тот же ID при Accepted → Accepted, новый ID после Declined или NotDecided, `null` при Declined, упавший вызов, который ничего не сохраняет, и новый `temporaryId` при каждом вызове
  - Зависит от: T2
- [x] **T4. Реализовать сервис identity**
  - Покрывает: R7, R8
  - Файлы: `src/identity/identityService.ts`, `src/identity/identityService.test.ts`
  - Что сделать: `start()` и `saveConsent()`, как в разделе «Компоненты и изменения»
  - Готово, когда: тесты показывают, что `start()` заполняет обсервер, успешное сохранение сливает статусы и ID в обсервер, а упавшее сохранение отклоняет промис и не трогает обсервер
  - Зависит от: T3
- [x] **T5. Добавить трёх запоминающих подписчиков**
  - Покрывает: R9
  - Файлы: `src/subscribers/recorder.ts`, `src/subscribers/requestHeaders.ts`, `src/subscribers/analyticsCollector.ts`, `src/subscribers/gameConfig.ts`, `src/subscribers/subscribers.test.ts`
  - Что сделать: `createRecorder` и три проекции из раздела «Поля подписчиков»
  - Готово, когда: тесты показывают наборы полей для обоих режимов `consentRequired`, отсутствие `deviceId` при `true`, отброшенные хедеры с `null`, сохранённый `null` у двух других и `updatedAt`, выставленный при каждом вызове
  - Зависит от: T2
- [x] **T6. Собрать блок согласия**
  - Покрывает: R3, R4, R5, R7
  - Файлы: `src/ui/ConsentBlock.tsx`, `src/ui/ConsentBlock.test.tsx`
  - Что сделать: компонент с обоими вариантами, переключателями, "Save", "Accept all", состояниями ожидания и ошибки (раздел «Видимость и поведение UI»); `App` его пока не рендерит
  - Готово, когда: тесты показывают, что выключенный переключатель сохраняет `Declined`, "Accept all" отправляет оба `Accepted`, кнопки отключены на время ожидания, а при ошибке виден текст ошибки и переключатели сохранены
  - Зависит от: T4
- [x] **T7. Собрать блок мониторинга**
  - Покрывает: R10
  - Файлы: `src/ui/MonitoringBlock.tsx`, `src/ui/MonitoringBlock.test.tsx`
  - Что сделать: рендерить состояние рекордера как JSON с временем обновления через `useSyncExternalStore` (раздел «Компоненты и изменения»); `App` его пока не рендерит
  - Готово, когда: тест показывает, что блок перерисовывается с новым состоянием и временем после вызова рекордера
  - Зависит от: T5
- [x] **T8. Собрать страницу**
  - Покрывает: R1, R2, R3, R4, R8, R10
  - Файлы: `src/main.tsx`, `src/App.tsx`, `src/App.test.tsx`
  - Что сделать: создать фейковый API из query-параметра `?consentRequired`, обсервер, сервис и рекордеры; `App` показывает загрузку, ошибку с "Retry", два блока по правилам видимости и три блока мониторинга (раздел «Компоненты и изменения»). Это точка входа в фичу, добавляется последней.
  - Готово, когда: тесты `App` показывают оба блока при `consentRequired = true` и NotDecided, только настройки, когда оба решены, и ни одного при `false`; страница работает в браузере
  - Зависит от: T6, T7
- [x] **T9. Пройти критерии приёмки**
  - Покрывает: `verify`

  - Готово, когда: каждый критерий проходит, а время в мониторинге меняется только при изменении поля
  - Зависит от: T8
