# Identity пользователя и согласие на трекинг — Задачи

Реализуют обсервер identity, фейковый бэкенд, трёх записывающих подписчиков, блок согласия и блоки мониторинга из [спецификации](./spec.md). Блоки монтируются на страницу в T9, после того как внутренние части протестированы.

## Задачи

- [ ] **T1. Создать каркас приложения**
  - Покрывает: `setup`
  - Файлы: `package.json`, `vite.config.ts`, `tsconfig.json`, `index.html`, `src/main.tsx`, `src/App.tsx`
  - Что сделать: создать приложение на React + Vite + TypeScript с Vitest, React Testing Library и jsdom (раздел «План тестирования»); `App` рендерит пустую страницу.
  - Готово, когда: `npm run build` и `npm test` проходят
  - Зависит от: —
- [ ] **T2. Добавить типы identity и фейковый метод конфига**
  - Покрывает: R1, R13
  - Файлы: `src/identity/types.ts`, `src/api/identityApi.ts`, `src/api/fake/latency.ts`, `src/api/fake/fakeIdentityApi.ts`, `src/api/fake/fakeIdentityApi.test.ts`
  - Что сделать: добавить типы и `IdentityApi` из раздела «API / интерфейсы», а также `getConfig()` с записью в `localStorage`, обоими режимами `consentRequired` и `withLatency` (раздел «Модель данных»).
  - Готово, когда: проходят тесты на постоянный `deviceId`, новый `temporaryId` при каждом вызове, tracking ID только для `Accepted`, оба `Accepted` с ID при `consentRequired`, равном `false`, отказ при доле ошибок `1` и заданную задержку
  - Зависит от: T1
- [ ] **T3. Добавить фейковый метод согласия**
  - Покрывает: R4, R6, R7, R13
  - Файлы: `src/api/fake/fakeIdentityApi.ts`, `src/api/fake/fakeIdentityApi.test.ts`
  - Что сделать: добавить `updateConsent(request)`, который сохраняет каждое переданное поле и возвращает оба tracking ID, как в разделе «Модель данных».
  - Готово, когда: проходят тесты на ID для `Accepted`, `null` для `Declined`, новый ID после повторного согласия, тот же ID при повторном принятии, отказ для `NotDecided`, сохранённый выбор у нового экземпляра на том же хранилище, неизменную запись при ошибке и некорректный JSON в хранилище
  - Зависит от: T2
- [ ] **T4. Добавить обсервер identity**
  - Покрывает: R8

  - Готово, когда: проходят тесты на первый вызов, вызов всех подписчиков при любом изменении, отсутствие вызова без изменения, текущие поля для позднего подписчика и то, что подписчик с исключением не мешает остальным
  - Зависит от: T2
- [ ] **T5. Добавить трёх записывающих подписчиков**
